# Workflow Template

Use for a source-grounded journey that crosses a meaningful conceptual boundary.

- State the trigger and observable outcome.
- Describe the ordered stages, state changes, branches, and failure exits that matter to readers.
- Name each participating domain or concept and link to its page.
- Include a diagram only when it makes the evidence-backed sequence clearer.
- Cite every material stage.

Use `type: workflow`, a clear `title`, non-empty `sources`, and `domains` when the workflow crosses
domain boundaries. Each source needs a stable `id` and an `inputs/sources/...#Lx-Ly` resource. Do not
create a workflow from an incidental call edge.
